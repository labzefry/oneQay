# oneQay — Integrated Business OS Command Center (2026-10-12)

Author by Lab | zefry

## Product intention

oneQay — The Future of Intelligent Business Management. Approved long-term direction is in `docs/handbook/ENTERPRISE_VISION.md`. The first usable business OS surface is delivered inside the existing protected merchant operations hub, without a parallel login, uncontrolled tenant switching, fabricated BI or a schema migration.

## Included implementation

- Enterprise Business Command Center on existing authenticated `GET /pos`: outlet-scoped real recorded completed sales, void counts, refund counts, gross totals grouped by currency, up to five latest authorized sales; no conflation of gross with net revenue/profit.
- Explicit restricted/unavailable reporting states, never zero substitutes.
- Deterministic operational signals from already-qualified catalog, shift and canonical sale read models, clearly **not generative AI**.
- Responsive command layout, tenant-safe authorized Business Suite directory, live links only to existing delivered `/pos/` routes, unavailable cards for unimplemented domains.
- Indonesian default / English using the existing reactive locale catalog and existing security/session shell.
- PHP read-model projection + focused denial/metric tests + frontend type-check/build workflow.
- No new migrations, database writes, payment provider, artificial demo financial data, or unsafe change to POS transaction services.

## Critical state honesty

This is a meaningful **Business OS presentation and read-side integration**, not the completion of E2–E5 enterprise product modules. Procurement, CRM, accounting, HRM, AI recommendation, and marketplace remain not delivered and cannot be clicked. Implement them with real source-owned data models, transactions, permission gates, tests and release evidence in subsequent integrated development packages; never claim a mock UI as a working capability.

The dashboard inherits the existing outlet + device scoped authority. Totals are *historical recorded gross*, prior to full void and refund adjustment and not a multi-outlet consolidated P&L. If reporting is denied or unavailable, it reports no numbers. No AI model or external billing provider is active.

## Deployment boundary

GitHub source/pull request does not deploy a cPanel host. Existing `oneqaydev` business-on source, runtime, merchant, sessions, credentials, official artifact and staging must remain unchanged until a new certified business-on UI successor artifact is built and applied through the previously proven hard-link-compatible operator. Preserve the working recovery point and current browser hashed assets. Require actual on-host `update-result.json`, subsequent verified HTTPS UI/source and owner-confirmed POS business acceptance before labeling this feature live.

## Next integrated functional product increments

1. Real tenant/outlet portfolio BI, date-filtered reporting, trend cohorts, inventory risk and stock turnover, constrained read models with complete correction semantics.
2. Procurement receiving and supplier lifecycle, CRM customer consent and contact policies, journal-based accounting with reconciled postings.
3. Workforce/approval workflows, cross-unit reporting and API integrations.
4. Tenant-safe AI recommendations with provenance, approval, prompt injection controls and reversible actions.
5. Marketplace/plugin trust boundaries and subscription billing only after capability tests and contractual provider readiness.

**Acceptance:** source correctness is gated by the dedicated Business OS CI; runtime acceptance is only established by independent deployment evidence.
